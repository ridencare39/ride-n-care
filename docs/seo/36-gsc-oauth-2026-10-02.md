## 1. The exact missing connection

The existing integration (`src/lib/gsc.server.ts`) talked to the Lovable connector gateway (`connector-gateway.lovable.dev/google_search_console`) with `LOVABLE_API_KEY` + `GOOGLE_SEARCH_CONSOLE_API_KEY`:

- The gateway does not exist in this Freebuff deployment (neither key is in any environment).
- Even with keys, Google rejects this API without OAuth 2.0: HTTP 401 `"API keys are not supported by this API. Expected OAuth2"` (verified earlier, recorded in `gsc-query-review.md` Batch 5).
- The owner's GSC **property is verified and showing real data** (dashboard reading: 322 clicks, 131 indexed pages, 90 not indexed, 17 valid breadcrumbs, no CWV yet) — only the **API credential** was missing.

## 2. What was implemented (read-only OAuth 2.0)

| Piece | File | Behavior |
| --- | --- | --- |
| OAuth client | `src/lib/gsc-oauth.server.ts` | Consent URL builder (`webmasters.readonly` ONLY), authorization-code exchange, refresh-token → access-token minting with in-memory cache, cookie helpers. |
| Flow endpoints | `src/server.ts` | `GET /gsc/connect` (302 → Google consent, CSRF state cookie) · `GET /gsc/oauth-callback` (state check → code exchange → HttpOnly refresh cookie `gsc_rt` 10 y → 302 `/seo-monitor?gsc=connected`) · `GET /gsc/disconnect` (clears cookie). GET-only (405 otherwise). |
| Data transport | `src/lib/gsc.server.ts` | Gateway replaced with Google's real endpoints + `Authorization: Bearer <access>`: `www.googleapis.com/webmasters/v3` (sites, searchAnalytics, sitemaps) and `searchconsole.googleapis.com/v1/urlInspection`. | Report builder | `src/lib/gsc.report.server.ts` | New statuses `not_configured` (keys missing, lists them) and `not_connected` (returns `connectUrl`); mints a token once per run; adds **near-me baseline** (the 4 priority queries: clicks, impressions, CTR, avg position, landing pages — every row tagged `source: gsc-api`). |
| Server fn | `src/lib/gsc.functions.ts` | Reads the refresh token from the request's HttpOnly cookie (admin gate unchanged: Supabase `has_role`). |
| Dashboard UI | `src/routes/_authenticated/seo-monitor.tsx` | Connect button, OAuth feedback banner (connected/disconnected/error with specific reasons), baseline table with "GSC API · live" badge, **visually separate** manual-observations section with "Manual — not API" badge, disconnect link. |
| Manual data | `src/lib/gsc-manual.ts` | Owner's dashboard reading stored with `source: "manual-observation"`, enteredAt 2026-10-02, explicit note that the displayed range was unspecified. |

**Security**: read-only scope; refresh token exists only in the connecting browser's HttpOnly cookie (never server-persisted, never logged, never in client JS); CSRF state cookie on the callback; client secret read from server env inside request handlers (documented Workers pattern); tokens never appear in URLs or logs.

## 3. Owner steps to complete the connection

1. Google Cloud Console → **APIs & Services → Library** → enable **Google Search Console API**.
2. **APIs & Services → OAuth consent screen** → External → add scope `https://www.googleapis.com/auth/webmasters.readonly` → add your Google account (the one with Owner/Full access on the property) as a test user. Prefer Publishing status **"In production"**; if Google forces verification first, stay in **Testing** and re-connect every 7 days (test-app refresh tokens expire).
3. **Credentials → Create credentials → OAuth client ID → Web application** → Authorized redirect URIs (exact):
   - `https://ridencare.co.in/gsc/oauth-callback`
   - `http://localhost:8080/gsc/oauth-callback`
   - `http://localhost:8081/gsc/oauth-callback`
4. Copy the Client ID + Client Secret into **Settings → Environment** as `GOOGLE_OAUTH_CLIENT_ID` and `GOOGLE_OAUTH_CLIENT_SECRET` (paste values to the agent, who will set them via `freebuff-env set`; values are never shown or logged).
5. Open `https://ridencare.co.in/seo-monitor` → **Connect Google Search Console** → approve the read-only consent.
